## 5. 板块二：寄存器地图与生活类比（20 分钟）

### 5.1 主隐喻：机器自带的固定格

**禁用「便利贴」**：便利贴可撕可贴，体现不出寄存器嵌在 CPU 上的固定性。

**主推实物：**

| 实物 | 像寄存器的点 |
|---|---|
| 收银机钱箱**分币格** | 格焊在机器里、数量少、格不动、里面硬币会变 |
| **电子计算器**显示窗 / M 存储 | 机器自带部件，跟着计算器走 |
| 汽车**仪表盘** | 表嵌在车上，数字变、表还在 |

**对比内存（预告第 4 次课）：** 身后**快递柜**——格很多、离手远、要专门跑一趟。

开场 30 秒：

1. 分币格会不会撕到另一边？——不会。  
2. 里面的数会不会变？——会。  
3. 收回：寄存器 = CPU 自带的、数量有限的固定格。

### 5.2 寄存器 ≠ 变量名

| 概念 | 说明 |
|---|---|
| 变量 | 源程序符号，像账本里的人名 |
| 寄存器 | CPU 内部固定格，指令直接读写 |
| 编译器 | 把人名装进固定格，或装进身后柜子（内存） |

### 5.3 必须记住的寄存器

| 寄存器 | 角色 | 生活类比 | 第 1–2 次课哪里见过 |
|---|---|---|---|
| `$zero` | 恒为 0 | 找零基准 / 零点参考 | `st.b $zero, ...` |
| `$sp` | 栈指针 | 餐盘摞的最顶 | `_start` 设栈 |
| `$ra` | 返回地址 | **作业续做断点**（见下） | `bl` / `jr $ra` |
| `$a0`–`$a7` | 参数；返回值主要 `$a0` | 联单固定栏 | 调用传参 |
| `$t0`–`$t8` | 临时计算 | 临时合计格 | `clear_bss` / `regs_alu.S` |

其余 `$s*` / `$fp` 等在第 6 次课展开。

### 5.3.0 寄存器有多宽？LA32 vs LA64（必讲，紧接总表）

只记「`$t0` 是临时」不够：还要问 **这一格里能装多少位**，以及 **指令从格子里取数时取多宽**。

#### （1）教材口径（读书笔记 2.1.2）

| 架构 | 整数通用寄存器 GR | 浮点寄存器 FR |
|---|---|---|
| **LA32** | **32 位**（`$r0`–`$r31` 每格 32 bit） | 64 位 |
| **LA64** | **64 位**（`$r0`–`$r31` 每格 64 bit） | 64 位 |

- **LA32 是 LA64 的子集**（笔记）：会 LA64 的 32 位运算路径，更容易对照教材里的 `.w` 例子。  
- **本课 miniOS**：交叉工具链 `loongarch64`、`lp64d` → 按 **LA64** 理解：每个 `$t0`/`$a0`/… 是 **64 位格**。  
- **别名相同、格子更深**：两边都叫 `$a0`，但 LA64 的 `$a0` 比 LA32 多出高 32 位。

生活比方（只辅助）：同一编号的收银分格，LA32 像「浅格只装 32 枚」，LA64 像「深格装 64 枚」——**编号还在，容量不同**。

#### （2）对「读寄存器 / 写寄存器」的影响

| 问题 | LA32 | LA64 |
|---|---|---|
| `add.d` 是否存在/是否主路径 | 整数侧以 32 位为主 | **有**；本课 demo 主用 `.d`，整格 64 位参与 |
| `add.w` 读源 | 整格就是 32 位 | **只读低 32 位**（高 32 位不参与这次 `.w` 运算） |
| `add.w` 写回 | 写满 32 位格 | 32 位结果 **符号扩展到 64 位** 再写入整格 |
| `$zero` | 32 位的 0 | 64 位的 0 |
| `$sp` / 地址 | 32 位地址空间视角 | LP64 下指针/地址按 **64 位** 更自然（与第 4 次课访存衔接） |
| 立即数扩到多宽 | 扩到 32 再运算（`.w`） | `addi.d` 扩到 64；`addi.w` 先 32 再按 `.w` 规则 |

教材/笔记原例（与 §5.5.1 同）：

```asm
add.w  r5, r2, r1
# LA32：r5 = r2 + r1
# LA64：r5[63:0] = SignExtend( r2[31:0] + r1[31:0] )
```

#### （3）学生易错

1. 以为 LA32/LA64 **寄存器名字不同**——名字可相同，**宽度不同**。  
2. 在 LA64 上对 `.w` 结果只看低 32 位、忘了高位被 **符号扩展** 填满。  
3. 把教材 `.w` 例子直接当成「已经按 64 位整格相加」。  
4. 本课验收串是 `.d` 小运算，**不代表**不用学 `.w` 与宽度差异。

#### （4）本课要求

- **能答：** 本课是 LA64；GR 每格 64 位。  
- **能答：** LA32 的 GR 是 32 位。  
- **能解释：** LA64 上 `add.w` 如何取数、如何写回（笔记公式）。  
- **能联系：** 后面立即数扩展、溢出例 `0x7fffffff` 都依赖「先固定寄存器宽度与后缀」。

#### （5）正数/负数在 32 位与 64 位寄存器中怎么存（课件第 13 页后专页）

寄存器只存比特；**有符号用补码**，**无符号用同一比特的另一种读法**。

| 十进制 | 32 位有符号存放 (hex) | 64 位有符号存放 (hex) |
|---|---|---|
| +10 | `0x0000000A` | `0x000000000000000A`（高位补 0） |
| −1 | `0xFFFFFFFF` | `0xFFFFFFFFFFFFFFFF`（高位补 1） |
| −2 | `0xFFFFFFFE` | `0xFFFFFFFFFFFFFFFE`（笔记 LA64 溢出结果） |
| 最大正 32 位 | `0x7FFFFFFF` | 铺到 64 位时常高 32 位为 0 |

**−2 的补码验算（32 位）：** `+2=0x00000002` → 取反 `0xFFFFFFFD` → 加 1 → `0xFFFFFFFE`。  
**同一比特无符号读：** `0xFFFFFFFE` → 4294967294（不是 −2）。

**32 位形态 → 64 位格：**

| 32 位 | 符号扩展到 64 | 零扩展到 64 |
|---|---|---|
| `0xFFFFFFFE`（−2） | `0xFFFFFFFFFFFFFFFE` | `0x00000000FFFFFFFE` |
| `0x80000000` | `0xFFFFFFFF80000000` | `0x0000000080000000` |

笔记 16 位例：`0x8000` 符号扩展到 32/64 位分别为 `0xFFFF8000` / `0xFFFFFFFFFFFF8000`（见 §5.7）。

开场 → ① 寄存器复习（职责/场景/$ra）
     → ② 宽度 LA32/LA64 + 有/无符号存放

**目标：** 合上讲义能默写本课 5 类寄存器职责，并能指回第 1–2 次课源码。
**复习① 必会集合（只考这些）**

| r 编号 | ABI 名 | 一句话职责 | 源码锚点 |
|---|---|---|---|
| **r0** | $zero | 恒 0 | `st.b r0`；`addi rd, r0, imm` |
| **r1** | $ra | 返回/续做地址 | `bl` 写入；`jr r1` |
| **r3** | $sp | 栈指针 | `_start` 设栈 |
| **r4–r11** | $a0–$a7 | 参数；返回值多在 r4 | 调用传参 |
| **r12–r20** | $t0–$t8 | 临时 | 中间结果 |

**课堂举例默认写 r0/r1/r4/r12**，不要只写 $t0/$a0。  
**宽度必会：** LA32 上 GR 每格 **32 位**；本课 LA64 每格 **64 位**。

其余（`$s*`/`$fp`/`$tp` 等）点名「第 6 次课再管保存规则」，本课不默写。

**复习② 源码点名（口述）**

打开 `boot/start.S`：谁设 `$sp`？谁改 `$ra`？谁用 `$t0/$t1/$zero`？  
打开 `lib/string.S`：参数在哪些 `$a*`？哪里用 `$t0` 保存原始指针？

**复习③ 场景快问**

| 问 | 答 |
|---|---|
| 第 1 个参数？ | `$a0` |
| 返回值？ | `$a0` |
| 中间和？ | `$t0`（等临时） |
| 清零写 0 的源？ | `$zero` |
| 调用后回来靠谁？ | `$ra` |

**复习④ 易混**

- `$ra`（位置）≠ `$a0`（数值）  
- `$t*`（临时）≠ `$a*`（约定参数栏）  
- `$zero` 不是可乱覆盖的草稿纸  

**复习⑤ 口诀**

> zero 永远零；sp 指栈顶；ra 记断点；a 传参返回；t 做临时。  
> 格是零件，不是便利贴。  
> LA32 格深 32，LA64 格深 64；`.w` 在 LA64 只取低 32 再符号扩展写回。

### 5.4 `$ra` 专讲（易错）

**不是**「我从哪间教室/哪间房来」（地理来源）。  
**是**「办完事后，主流程从哪一步接着做」（续做断点）。

主例——写作业时接电话：

| 生活 | 硬件 |
|---|---|
| 做到第 3 题第 2 小问 | 主程序进行中 |
| 电话响，要去接 | 即将 `bl` |
| 记下：回来接着做 3-(2) | `bl` 把返回地址写入 `$ra` |
| 接电话 | 子程序执行 |
| 挂断，按记下的题号续写 | `jr $ra` |

落到源码：

```asm
    bl    clear_bss      /* $ra ← 下一条 */
    bl    kernel_main    /* clear_bss 的 jr $ra 回到这里 */
```

**区分：** `$ra` = 回到哪条指令；`$a0` = 函数算出的数（返回值）。

### 5.5 数据表示：位宽后缀（必须落到指令）

教材：助记符 ≈ **指令名 + 后缀**。

| 后缀 | 宽度 | 生活比方 | 指令举例 |
|---|---|---|---|
| `.b` | 1 字节 = 8 位 | 最小快递盒 | `st.b`；教材 `ld.b` |
| `.h` | 2 字节 | 小盒 | `ld.h`/`st.h`（第 4 次课多用） |
| `.w` | 4 字节 = 32 位 | 中箱 | `add.w`/`addi.w`（教材常用） |
| `.d` | 8 字节 = 64 位 | 超大箱 | 本课 `addi.d`/`add.d`/`sub.d` |
| `.bu`/`.hu`/`.wu` | 无符号加载 | 只零扩展、不当负数 | `ld.bu` 等 → 第 4 次课系统练 |

**关键句：** 后缀先告诉你「按多宽解释/运算」，再谈有符号还是无符号。

### 5.5.1 LA32 与 LA64：对「指令取数」的影响（本课必讲）

教材与手册把龙芯基础整数架构分为 **LA32** 与 **LA64**。  
**取数**在这里指：指令从寄存器/立即数里**拿出多宽、怎么解释、写回多宽**——不是指第 4 次课的内存 load 全家桶。

#### （1）先比硬件与本课平台

| 项目 | LA32 | LA64（本课 miniOS） |
|---|---|---|
| 整数通用寄存器 GR | **32 位** | **64 位** |
| 浮点寄存器 FR | 64 位 | 64 位 |
| 与另一者的关系 | LA64 的**子集** | 在子集之上增加 64 位运算等 |
| 本课工具链线索 | — | `-march=loongarch64`、`-mabi=lp64d` |

**一句话：** 同一助记符家族，在 LA32/LA64 上「寄存器格子有多宽、.w 运算后高位怎么填」可以不同。

#### （2）指令后缀与「取哪一段」

| 后缀 | 取数宽度 | LA32 上 | LA64 上 |
|---|---|---|---|
| `.w` | 32 位（字） | 主流算术/逻辑（寄存器本身就是 32 位） | **只取源寄存器低 32 位**参与运算 |
| `.d` | 64 位（双字） | **无**（或不作为整数主路径） | 本课 `add.d`/`addi.d`/`sub.d`/`mul.d` 主路径 |
| `.b`/`.h` | 8/16 位 | 多见于访存等 | 同；本课 `st.b` 点到 |

**LA64 上 `add.w` 的典型取数/写回口径（教材）：**

```text
读：只取 GR[rj]、GR[rk] 的低 32 位
算：按 32 位做加法
写：把 32 位结果 符号扩展到 64 位，再写入 GR[rd]
```

示意：

```asm
# LA64
add.w  $r5, $r2, $r1
# 等价理解：
#   tmp32 = r2[31:0] + r1[31:0]
#   r5    = SignExtend(tmp32, 64)

add.d  $r5, $r2, $r1
#   r5 = r2[63:0] + r1[63:0]   # 整格 64 位都参与
```

**教材例（读书笔记转述）：**

```asm
add.w  r5, r2, r1
# LA32：r5 = r2 + r1（寄存器即 32 位）
# LA64：r5[63:0] = SignExtend( r2[31:0] + r1[31:0] )
```

#### （3）对立即数取数的影响

| 指令族 | 立即数 | 扩展到哪 |
|---|---|---|
| `addi.w` | si12 | 先符号扩展到 **32**，再按 `.w` 规则与低 32 位相加；LA64 写回时常再符号扩展到 64 |
| `addi.d` | si12 | 符号扩展到 **64**，再与 64 位 `rj` 相加（本课常用） |
| `andi/ori/xori` | ui12 | 按位模式零扩展到当前架构寄存器宽度 |

教材装立即数路径（§3.1.1）：`imm < 12 bit` 用 `addi.* rd, r0, imm`；更大用 `lu12i.w` + `ori` 等（见下节）。
#### （4）为何本课 demo 几乎全用 `.d`

1. QEMU/`loongarch64` 工具链默认是 **LA64 视角**。  
2. 先建立「整格 64 位寄存器」的直觉，少在高位符号扩展上绕晕。  
3. 教材里大量 `.w` 例子要会**对照阅读**，并知道：在 LA64 上看到 `add.w` 时，**取数只看低 32 位、写回要符号扩展**。  
4. 指针、地址在 LP64 下是 64 位 → 地址加减更自然用 `.d`（与第 4 次课访存衔接）。

#### （5）课堂必须带走的三句

1. **LA32：GR 32 位；LA64：GR 64 位；LA32 ⊂ 能力上更接近 LA64 的子集。**  
2. **LA64 的 `.w`：取低 32 位算，结果符号扩展回 64 位写回。**  
3. **本课实验/验收：`.d` 主路径；见到 `.w` 要会解释取数差异。**

### 5.6 立即数：如何「读进」寄存器（本课必讲透）

指令里的常数叫**立即数（immediate）**。它写在指令编码里，**不是**先躺在某个内存变量里。

> 举例原则：理论讲解优先用《汇编语言编程基础 基于 LoongArch》及  
> [读书笔记](https://blog.csdn.net/loongsoner/article/details/128977015) 中的数例；  
> miniOS 验收串数字仅用于 `make run` 对照，不替代教材例。

#### （1）小立即数：`addi` + `r0`/`$zero`（教材 §3.1.1）

笔记口径（LA32/通用写法）：

```asm
addi.w  rd, r0, imm[11:0]    # imm < 12 bit 时装入
# 本课 LA64 demo 对应常用：
addi.d  $t0, $zero, imm12
```

- `si12` 先做符号扩展再参与运算（与第 2 章「符号扩展」表一致）。  
- 本仓库 `clear_bss` 中 `addi.d $t0, $t0, 1` 是「寄存器 + 立即数 1」，同属 `addi` 族。

#### （2）逻辑类立即数：`andi`（教材例）

笔记例：

```asm
# 若 r2 == 0x7f0
andi  r5, r2, 3      # r5 = 0
```

教材补充：`andi` 可判断对齐——地址与 `0x7` 做与，结果为 0 则 8 字节对齐。

- **`addi` 的 imm：有符号 si**；**`andi/ori/xori` 的 imm：无符号 ui 位模式**。

#### （3）中等/大立即数：拼装（教材 §3.1.1 原文路径）

笔记中的分层（按 imm 位宽）：

```asm
# 12 bit < imm < 32 bit 时，先装高位再拼低位：
lu12i.w  rd,     imm[31:12]
ori      rd, rd, imm[11:0]

# 再配合 add.w 等使用（笔记中「立即数的 32 位加法」）：
lu12i.w  r1, imm[31:12]
ori      r1, r1, imm[11:0]
add.w    r5, r2, r1
```

伪指令（笔记）：`li.w rd, imm32` / `li.d rd, imm64`（由汇编器展开）。

**课堂要求：** 会判断能否一条 `addi`；会说 `lu12i`+`ori`/`li`；实验不要求手写拼装。

#### （4）`move`（教材/笔记）

```text
move rd, rj  ⇔  or rd, rj, r0
# 例：move $r12, $r1  ⇔  or $r12, $r1, $r0
```

### 5.7 有符号数 vs 无符号数（不同位宽，本课必讲透）

#### （1）符号扩展表（教材第 2 章笔记例）

对 **16 位立即数** 做扩展时（笔记表）：

| 种类 | 对 `0x8000` | 对 `0x1000` |
|---|---|---|
| 32 位符号扩展 | `0xFFFF8000` | `0x00001000` |
| 32 位零扩展 | `0x00008000` | `0x00001000` |
| 64 位符号扩展 | `0xFFFFFFFFFFFF8000` | `0x0000000000001000` |
| 64 位零扩展 | `0x0000000000008000` | `0x0000000000001000` |

**技术收回：** 同一比特，**扩展方式**不同，进入宽寄存器后的值不同。

#### （2）扩展指令例：`ext.w.h`（教材 §3.1.4 笔记）

```asm
# 若 r4 == 0x000000000000FFFA
ext.w.h  r5, r4
# r5 = 0xFFFFFFFFFFFFFFFA
```

说明：半字按**有符号**扩展到字/再进入 64 位寄存器后的形态（笔记结果）。  
本课可跑的 `ext.w.b` 同属「窄数据有符号扩展」族；验收串用 `0x7f→127` 仅作运行对照。

#### （3）`andi` 与对齐（教材逻辑节）

见上节 `r2=0x7f0; andi r5,r2,3 → 0`。  
与「有符号扩展」不同：`andi` 做的是**按位与**，结果按位模式理解。

#### （3）条件赋值族：`slt` / `sltu` / `maskeqz`（教材 §3.1.2）

**语义（笔记指令表）：**

| 指令 | 功能简述 |
|---|---|
| `slt rd, rj, rk` | `rd = (rj < rk) ? 1 : 0`（**有符号**） |
| `sltu rd, rj, rk` | 同上，**无符号**比较 |
| `slti` / `sltui` | 与立即数比较（有/无符号） |
| `maskeqz rd, rj, rk` | `rd = (rk == 0) ? 0 : rj` |
| `masknez rd, rj, rk` | `rd = (rk != 0) ? 0 : rj` |

**`slt` vs `sltu`（必讲清）：**

```asm
slt   $t0, $a0, $a1    # 有符号 < 
sltu  $t0, $a0, $a1    # 无符号 <
```

- 最高位为 1 的「无符号大正数」，用 `slt` 会当成负数，**大小关系可能颠倒**。  
- 地址、长度、缓冲区边界常用 **无符号** 视角 → 多看 `sltu`。  
- 本课 `make run` 验收：`slt` 且 `(3<5)=1`（运行对照）。

**`maskeqz` / `masknez`（笔记「取最小值」例，优先用此代码）：**

笔记：求 `a = (b < c) ? b : c`（最小值），设 `r6==a, r4==b, r5==c`：

```asm
slt      r12, r4, r5      # r12 = (b < c) ? 1 : 0
maskeqz  r4,  r4, r12     # r4  = (r12 == 0) ? 0 : b
masknez  r12, r5, r12     # r12 = (r12 != 0) ? 0 : c
or       r6,  r4, r12     # a = r4 | r12
```

- `maskeqz`：条件寄存器为 **0** 时把结果清 0，否则保留 `rj`。  
- `masknez`：条件寄存器 **非 0** 时清 0，否则保留 `rj`。  
- 与 `slt` 组合可实现**无分支**的 min/max 类选择（笔记校正过取最大/最小写法，课堂以「会读 maskeqz 语义」为准）。  
- 本课 **不要求** 在 miniOS 里新增 min 函数；**要求会读笔记四条指令在干什么**。
#### （4）位宽、`.w`/`.d` 与 LA32/LA64（接 §5.5.1）

- 本课 demo 用 **`.d`（64 位）** 做加减乘。  
- 教材 **`.w`** 在 **LA64** 上：取低 32 位算，结果**符号扩展**写回 64 位 GR。  
- 32 位有符号溢出后再扩展到 64 位，看起来仍像「负数」——与「无符号 32 位大正数」不是同一解释。  
- 不要默认「所有教材例子的寄存器都是 32 位」或「都是 64 位」——先问 **LA32 还是 LA64**。

### 5.7.5 溢出（overflow）：原理 + 教材例

**溢出** = 按选定的**位宽 + 有/无符号规则**，数学真值无法用该宽度表示，硬件仍按补码规则写回比特串。

#### （1）表示范围（笔记口径）

寄存器最高位为符号位。笔记给出（有符号解读）：

```text
LA32：约 [0x80000000 , 0x7FFFFFFF]
LA64：约 [0x8000000000000000 , 0x7FFFFFFFFFFFFFFF]  （笔记写法）
```

#### （2）教材/笔记溢出例（优先用此例，勿另造）

```asm
add.w  r5, r1, r1
# 设 r1 = 0x7fffffff
# LA32：r5 = 0xfffffffe   （有符号读作 -2）
# LA64：r5 = 0xfffffffffffffffe  （有符号读作 -2）
```

出处：读书笔记「3.1.1 算术运算指令 · 溢出问题」。

**原理：** `0x7fffffff` 为 32 位最大正数；再加自身超出有符号 32 位上限，补码结果变为 `0xfffffffe`（−2）。  
**LA64：** 该 32 位结果再**符号扩展**到 64 位，高位全 1，读起来仍是 −2——不是「又在 64 位里重新算爆了」，而是 **32 位溢出结果被扩展**。

#### （3）与 ARM 等的差异（笔记）

- ARM 可用 CPSR 等保存进位、溢出等标志。  
- LoongArch 无同等「统一状态寄存器」讲法；笔记：可通过**目的寄存器与源寄存器符号位是否一致**等办法判断。  
- 需要可靠检查时：换更宽运算（如 `.d`）、或软件判断。

#### （4）课堂三问（溢出）

1. 按几位、有符号还是无符号？LA32 还是 LA64？  
2. 是否采用笔记例：`r1=0x7fffffff; add.w r5,r1,r1`？  
3. LA32 与 LA64 写出的 `r5` 比特有何不同、十进制为何都是 −2？

**板书金句：**

> 先问 LA32/LA64 与位宽，再问有符号还是无符号。  
> 溢出教材例：0x7fffffff+自身 → 0xfffffffe → −2；LA64 再符号扩展仍为 −2。  
> LA64 的 .w：取低 32 位算，符号扩展写回。  
> 立即数：addi(si) / andi(ui，笔记 0x7f0&3) / 大数 lu12i+ori。

### 5.8 第 4 章浮点（边界）

- `$f*`、`fadd.s` 等；本课实验不跑。

### 6.1 算术：`(a+b)-c` / `mul.d`（完整执行表，**r 编号**）

```asm
# a=3,b=5,c=2 → 6；r4=a, r5=b, r6=c, r12=临时, r1=返回地址

sub.d  r4, r12, r6
jr     r1
```

| 步 | 指令 | 计算 | r4 | r5 | r6 | r12 |
|---|---|---|---|---|---|---|
| 0 | 入口 | — | 3 | 5 | 2 | ? |
| 1 | add.d r12,r4,r5 | 3+5=8 | 3 | 5 | 2 | **8** |
| 2 | sub.d r4,r12,r6 | 8-2=6 | **6** | 5 | 2 | 8 |
| 3 | jr r1 | 返回 | 6 | 5 | 2 | 8 |
