## 5. 单元二：综合展示（第 3–4 学时）

### Task5 命令行 shell 骨架（必做）

板级迁移本身工作量填不满 4 学时，这个 Task 把"内核还能再补哪些功能"落成
一个所有人都做、但支持的命令集可深可浅的具体产出：一个跑在 miniOS 里的
最小命令行 shell。做完这个 Task 才有东西可以在 Task6 的展示里现场敲。

按 Task5.1 → 5.2 → 5.3 → 5.4 的顺序做，每完成一步先 `make run` 在 QEMU
里确认没改坏前面的验收输出，再往下走——这几步互相依赖（Task5.3 的
`meminfo`/`crash` 命令要调用 Task5.1/5.2 写好的函数），乱序容易调试到
搞不清是哪一步的问题。**有真实 2K0300 板卡的同学，Task5.4 做完之后这个
shell 应该能在真机上真正敲起来，不只是 QEMU 演示**，这是这次课新确认
出来的结果，见下面 Task5.4。

**Task5.1 最小内核堆分配器**

实现 `kmalloc`/`kfree`，接口：

```c
void *kmalloc(size_t size);
void kfree(void *ptr);
void kmalloc_stats(unsigned long *used, unsigned long *capacity,
                    unsigned long *free_blocks);
```

- 堆本体用一段静态数组（不依赖 MMU/分页，跟 `boot_stack` 是同一类"编译期
  留好一块内存"的思路），维护一个"从未分配过区域"的位置指针。
- 每块分配出去的内存前面放一个小 header（至少记录大小），`kfree` 时靠
  指针减法找回 header，挂进一条空闲链表。
- `kmalloc` 优先从空闲链表里找能复用的旧块（大小够用即可，不要求最优），
  找不到再从"从未分配过"的区域切新的。
- 不要求写相邻空闲块合并（coalescing）——这是有意留下的真实局限，先把
  "能分配、能回收复用"这条链路跑通即可。

**Task5.2 异常分类**

在第 9–11 次课已有的 `exception_handler` 基础上，把 `ESTAT.Ecode` 翻译成
人能看懂的名字（至少覆盖 ADE/ALE/SYS/BRK/INE 这 5 种，编码查 LoongArch
参考手册异常编码表），打印格式类似 `[exception] BRK(断点) ESTAT=0x... ERA=0x...`。

**Task5.3 `uart_getc` + 命令行循环**

之前的课只教过 `uart_putc`（发送），没教过接收——这里先补一个 `uart_getc`：

```c
char uart_getc(void);
```

跟 `uart_putc` 等 `LSR` 的 TX_EMPTY 位是对称的思路：等 `LSR` 的
"接收数据就绪"位（16550 标准里通常是 bit0，`LSR_DATA_READY_MASK
0x01`）置位，再从数据寄存器（跟 `uart_putc` 写的是同一个偏移，16550
里发送/接收共用一个地址，读为 RBR、写为 THR）读一个字节返回。

有了 `uart_getc`，按下面几个子步骤搭命令行循环，建议逐步验证（先只做
读行+回显，能看到自己敲的字符再加分发逻辑，分头调试比一次写完再测省
时间）：

1. **读一行**：从 `uart_getc` 逐字符读，遇到 `\r` 或 `\n` 结束这一行
   （换行本身要往回发 `\r\n`，不能只发一个）；遇到退格
   （`0x7f` 或 `0x08`）要往回删一个字符（本地缓冲区回退 + 往串口发
   "退一格"的控制序列，不是简单丢弃）；每读到一个普通字符要**立刻回显**
   （把这个字符写回串口）——QEMU 的 `-serial stdio` 和大多数真实串口
   终端都不会帮你自动回显，不回显的话用户敲了字看不到自己敲了什么。
2. **切分命令**：一行读完后，找第一个空格，切成"命令名"（空格前）+
   "参数"（空格后，去掉多余的前导空格，可能是空字符串）。
3. **分发**：拿命令名依次和已知命令名比较（`strcmp`，第 7 次课已经
   实现过），匹配上就调对应的处理函数，都不匹配就打印"未知命令"之类
   的提示，不要什么都不做——用户敲错命令需要看到反馈。
4. **循环**：处理完一条命令，打印一个提示符（比如 `> `），回到第 1
   步继续读下一行——这是个不会退出的死循环，是 shell 该有的样子。

至少内置这 4 个命令：

| 命令 | 行为 |
|---|---|
| `help` | 列出当前支持的命令名 |
| `echo <text>` | 原样打印 `<text>` |
| `meminfo` | 调 `kmalloc_stats`，打印已用/容量/空闲块数 |
| `crash <ade\|ale\|sys\|brk\|ine>` | 按参数触发对应异常，验证 Task5.2 的分类打印 |

写完先在 QEMU 里手动敲这 4 个命令逐条验证，行为符合预期再往下做
Task5.4。

**Task5.4 把 shell 挪到真机安全触发位置（决定它能不能在真机上跑起来）**

这一步不是新写代码，是调整**已有代码摆放的位置**，但很关键——摆错位置
会导致 shell 在真机上完全摸不到，QEMU 上却看不出问题（QEMU 不受这个
限制）。

背景：`exception_init()` 本身很安全，只是把处理函数地址写进
`CSR.EENTRY`，不会主动触发任何异常/中断。**真正危险的是"真的撞出一次
异常或中断"**——2K0300 真机上一旦发生（不限于 `break`，定时器 tick 走
的也是同一条入口路径，同样会卡住），会卡进一段固件级的"未处理异常"转储
里，回不来了，这是 Task4 记录的已知边界（`board_2k0300_setup.md`）。

如果按"从上往下顺序写代码"的直觉，会把 `exception_init()` 之后紧跟着
自动触发一次 `break`（第 9 次课demo）、再自动使能一次定时器中断（第
11 次课demo）、最后才轮到 Task5 的 shell——这样一来，真机上代码执行到
自动 `break` 那一步就已经卡住了，shell 永远排不上号，哪怕 shell 本身
写得完全正确。

**改法**：`exception_init()` 调用完之后，**立刻**进入 Task5 的 shell
循环，不要让任何自动触发异常/中断的代码排在 shell 前面。具体来说：

- 第 9 次课原来"自动执行一次 `break 0`"这段代码不要再自动跑——改成只
  有用户在 shell 里敲 `crash brk` 才会触发，复用 Task5.3 已经写好的
  `crash` 命令即可，不用新写。
- 第 11 次课原来"自动使能定时器、收集 5 次 tick"这段代码，同样改成
  一个新的 shell 命令（比如叫 `timer`），用户敲了才跑。**注意**：
  `irq_ticks()` 是一个全局递增的计数器，不会自动清零——如果直接写
  `while (irq_ticks() < 5)`，这个命令被敲第二次时，计数器可能早就
  超过 5 了，会立刻返回、什么都等不到；正确写法是先记下调用这一刻的
  `irq_ticks()` 读数，用**这次调用前后的差值**跟 5 比较，保证每次敲
  这个命令都会等到 5 个新 tick。

改完之后，QEMU 上重新走一遍 week01-11 的原有验收，确认输出没有变化
（只是触发方式从"自动"变成了"敲命令触发"，内容应该完全一样）；有真实
板卡的同学，照 `board_2k0300_setup.md` §5-§7 重新编译、传输、`go`，这次
预期能看到 week01-08 输出之后紧接着出现 `week12-shell check done` 和
交互提示符，可以真的在真机上敲 `help`/`echo`/`meminfo`（`crash`/
`timer` 一旦真的触发异常/中断，大概率还是会撞上前面说的已知边界，这
属于预期内，不用觉得是自己代码写错了）。

**验收标准**：`make run` 后能在 QEMU 串口交互式敲 Task5.3 的 4 个命令，
shell 循环开始前（进入第一次读命令之前）打印一次 `week12-shell check
done`（只在启动时出现一次，不是每条命令都打印）。有真实板卡的同学，
按 Task5.4 调整位置后，`help`/`echo`/`meminfo` 应该能在真机上跑通；
`crash`/`timer` 因为会真的触发异常/中断，真机上可能撞上已知边界，不
强制。

### 给 shell 加自己的命令（不限于以上 4 个，Task6 选题 C 可能用得上）

Task5.3 的分发逻辑本质是一长串"命令名对不对得上"的判断，加一个新命令
不需要改结构，只需要照抄这个模式：

1. 写一个处理函数，签名统一成"接收参数字符串，自己决定要不要再切分"，
   比如 `void cmd_xxx(const char *arg)`。
2. 在分发逻辑里加一个新的比较分支：命令名对上了就调这个函数。
3. `help` 命令的输出里把新命令名也加进去，别让它变成一个"能用但没人
   知道"的隐藏命令。

新命令想干什么，可以是很简单的东西（比如打印一句固定的话，或者读写一个
全局变量），也可以调用你自己另外写的功能模块——这个骨架本身不限制命令
能做多复杂，只规定了"怎么接进来"这一个规则。想清楚"这个命令替 miniOS
补上了哪一类通用操作系统才有的能力"，比单纯堆命令数量更有意义。

## 11. 常见故障速查

| Ubuntu 中找不到工具 | 按 `docs/student_env_runbook.md` 安装课程工具链 |
| 板端完全无输出 | 先确认是否跑到 `_start`、加载方式、时钟配置 |
| 板端输出乱码 | 优先怀疑波特率/时钟 |
| Task5 shell 里一次粘贴多条命令后串成一条乱码/命令名对不上 | `uart_getc` 这个最小实现没有流控，真机上一次涌进一长串字符容易丢字节，粘贴前如果开着中文输入法，候选框里的残留文字也可能混进剪贴板——**一条一条手动敲回车**，不要一次性粘贴多行，不是代码有 bug |
| 退不出 QEMU | `Ctrl+a`，再按 `x` |
