## 4. 单元一：板级迁移（第 1–2 学时）

### Task1 差异表

填写入口地址、UART 基址、加载方式、调试手段对照（QEMU virt vs 2K0300）。
这四项在 2K0300 这一列不是查个表抄一下就行，按下面的方法去查/推/验证：

1. **先看板卡官方资料**：`docs/12/board_2k0300_setup.md` §0 有网盘链接，
   拿到《2K0300 先锋派快速使用指南》——但这类"快速上手指南"通常只讲怎么用
   （怎么接线、怎么进 U-Boot），**不一定有寄存器地址**，别指望在这里直接
   抄到答案。
2. **UART 基址更快的查法**：把板子跑起来（走到预置的 Linux/Busybox 系统），
   `ls -l /sys/class/tty/ttyS*` 能看到每个 `ttyS*` 对应的真实物理地址
   （设备节点路径里带十六进制地址）；再确认哪个 `ttyS*` 是你接的那个调试口
   （提示：`cat /proc/cmdline` 或看内核启动参数里的 `console=` 一般会点明）。
   这比啃手册快得多，而且是真机报告的真实值。**不要直接照抄 QEMU 版
   `include/uart.h` 里的地址**——QEMU 是软件模拟出来的地址，跟任何真实
   芯片的物理地址映射没有必然关系。
3. **入口地址更麻烦一点**：U-Boot 启动日志（`reboot` 时刷屏那一堆）里
   `Load Address`/`Booting kernel from ... at ...` 这类字段是线索，能告诉你
   "加载器把内核放在哪个地址"，但**不能证明**"CPU 跳过去执行的那一刻，
   地址翻译/缓存这些前提条件已经配置成你以为的那样"——这一项只能靠 Task4
   实际上板测试来验证，不是纸面推导就能确定的，Task1 里先写出你的"假设值
   + 依据"，验证结果留到 Task4 里更新。
4. **加载方式、调试手段**：读 `docs/12/board_2k0300_setup.md` 和快速指南里
   提到的 U-Boot 菜单选项（`bootmenu` 里能看到哪几种更新/加载方式），
   结合你手上这块板子实际支持的接口（有没有网口、SD 卡槽）判断。

### Task2 修改点清单

**目标：让 `make PLATFORM=2k0300` 能编译出一个 2K0300 专用的 `minios.bin`**
（`PLATFORM` 这个开关名你自己定），QEMU 路径（`make PLATFORM=qemu_virt`
或不带参数时的默认行为）必须保持不受影响、行为不变。这不只是"列个清单"，
要真的改代码、能编译过。

排查"哪些文件是 QEMU 专属、需要按平台拆开"的方法：把下面每个文件打开，
逐处问自己"这一行换一颗芯片还成立吗"：

| 文件 | 检查点 |
|---|---|
| `kernel/linker.ld` | `.` 起始地址是不是写死的 QEMU 窗口 |
| `include/uart.h` | `UART0_BASE` 是不是写死的 QEMU 模拟地址 |
| `kernel/printk.c` | `uart_putc` 有没有轮询发送状态寄存器（真实硬件不轮询大概率丢字符/死等，QEMU 的简单 16550 模型可能一直"假装就绪"掩盖了这个问题） |
| `Makefile` | `QEMU_MACHINE`、交叉编译参数等有没有写死 QEMU 相关的东西；有没有平台切换开关 |
| `boot/start.S` | 检查是否需要为真实硬件补充启动初始化（比如 CPU/内存相关的配置），还是"骨架不变"这一条依然成立 |

设计上可以参考"给不同平台分别建头文件/链接脚本，用宏或 Makefile 变量切换"
这类常见做法，具体怎么组织目录、宏叫什么名字自己定，只要满足开头那条
"两个平台都能编译、QEMU 不受影响"的硬性要求。

### Task3 排错顺序

- 写出：`_start` → `$sp` → `clear_bss` → UART 的定位顺序，对照讲义 §4.4 故障分层表。
- 结合 `docs/12/board_2k0300_setup.md` §6 的排错方法论表（传输成功≠地址对、
  外设和内存可能需要不同类型的地址窗口这类真实会遇到的坑），说明"卡死"
  这一个现象背后其实可能有好几种完全不同的原因，你打算怎么一步步区分它们。

### Task4 板端实践

**人手一块真实 2K0300 板卡，这一项是必做项，不是"有条件才做"。**

- 先看 [board_2k0300_setup.md](board_2k0300_setup.md) 把接线/驱动/串口连通
  这一层跑通（不含移植代码答案，芯片参数仍要靠 Task1 自己查）。
- **验收标准（明确封顶）**：板端跑通 week01–08 的全部验收输出（含浮点），
  与 QEMU 版逐字节一致，即算完成。**week09（`break` 异常测试）起卡住是
  已知的、当前还没解决的边界，不要求解决**——原因是 LoongArch 真机在
  `PG=1` 分页模式下的异常向量行为和 QEMU 的 `DA=1` 直接地址模式不一样，
  需要官方寄存器手册或参考代码才能继续排查，课堂时间内不强求。跑到
  week09 卡住、能清楚复现现象、说得出已经排除了哪些可能（比如"确认过不是
  栈指针的问题"）比稀里糊涂"卡住不知道为什么"更值得分。
- 极少数板卡本身有问题（烧坏/买错型号）确实连不上的，走完整模拟方案
  + 风险分析（哪一步最可能出问题、如何验证）作为兜底，需要跟老师说明
  情况。

## 11. 常见故障速查

| 现象 | 处理 |
|---|---|
| PowerShell 报 `ObjectNotFound: make` | 先 `wsl -d Ubuntu` 进入 Ubuntu，再 `cd` 仓库后 `make` |
| `wsl -d Ubuntu` 失败 | `wsl -l -v` 核对发行版名称 |
| Ubuntu 中找不到工具 | 按 `docs/student_env_runbook.md` 安装课程工具链 |
| 板端完全无输出 | 先确认是否跑到 `_start`、加载方式、时钟配置 |
| 板端输出乱码 | 优先怀疑波特率/时钟 |
| 退不出 QEMU | `Ctrl+a`，再按 `x` |
