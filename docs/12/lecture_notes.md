## 0. 一句话目标

先把同一套 miniOS 最小链路迁到龙芯 2K0300（能启动、能稳定出字符），再用 5–8 分钟讲清整门课主线，完成一个可运行、可讲解的综合展示。

## 1. 课程定位（Why）

这是全课程最后一次课，4 学时连排，分两个前后衔接的单元：

```text
单元一（第 1–2 学时）：板级迁移
  QEMU 的价值：快、可重复、易调试
  板子的价值：真实约束与外设
  移植不是重写 OS——保留启动逻辑/段模型/调用约定/分层，只替换平台相关层
                              ↓
单元二（第 3–4 学时）：综合展示
  把移植经验并入全课程主线复盘：从一条 la.global $sp 开始，
  得到可承载日志与运行骨架的最小系统软件底座，并指向 Agent OS
```

终局故事一句话：

> 从一条 `la.global $sp, ...` 开始，我们得到可承载日志与运行骨架的最小系统软件底座；把同一套底座迁到真实板子、讲清楚它的来龙去脉，就是这门课的收尾。

## 4. 单元一：板级迁移

### 4.1 差异表（课堂共填）

| 项目 | QEMU virt | 2K0300 |
|---|---|---|
| 入口/装载地址 | `linker.ld` 当前窗口 | 以板级为准 |
| UART 基址 | `include/uart.h` | SoC 映射 |
| 时钟/波特率 | 常可简化 | 通常必须 init |
| 调试 | GDB stub 方便 | 串口日志 + 厂商工具 |
| 加载 | `-kernel ELF` | 厂商加载/Flash 等 |

### 4.2 不变的启动骨架

```asm
_start:
    la.global $sp, boot_stack_top
    bl        clear_bss
    bl        kernel_main
halt:
    idle      0
    b         halt
```

1. 算法骨架通常不变，变的是链接地址是否让这些符号落在正确窗口。
2. 排错顺序：**是否执行到 `_start` → `$sp` → `clear_bss` → UART**。

### 4.3 UART 适配步骤

1. 查基址、THR/LSR 偏移。
2. 需要则写 `uart_init`（分频、LCR 等）。
3. `uart_putc` 改为等 TX 空再写：

```asm
wait_tx:
    ld.bu   $t1, $t0, LSR_OFF
    andi    $t1, $t1, TX_EMPTY_MASK
    beqz    $t1, wait_tx
    st.b    $a0, $t0, THR_OFF
    jr      $ra
```

4. 再接 `printk`。综合第 3–5、9 次课能力。

### 4.4 故障分层

| 现象 | 先查 |
|---|---|
| 完全无输出 | 是否跑到 `_start`、加载、时钟 |
| 乱码 | 波特率/时钟 |
| 仅首字符 | 发送等待逻辑 |
| 输出后异常复位 | 异常未处理/看门狗等 |

### 单元一课堂 Demo

2. 展示"只改平台文件"的目录策略。
3. 记录一次真实失败与修复（很有教学价值）。

## 5. 单元二：综合展示

### 5.1 综合 demo 选题

**选题 A：启动与服务（稳健）**　Hello + data/bss 自检；可选 `sys_write` 日志；可选异常打印。

**选题 B：板级迁移**　QEMU 与 2K0300 对照；UART 适配要点；差异表讲解（直接复用单元一成果）。

**选题 C：Agent Runtime 雏形**　能力自检/心跳日志；明确依赖哪些内核服务；诚实列出缺口（调度、隔离、存储等）。可直接复用 lab.md Task5 的命令行 shell 作骨架。

### 5.2 终局必讲汇编

启动路径（应能脱稿）：

```asm
_start:
    la.global $sp, boot_stack_top
    bl        clear_bss
    bl        kernel_main
halt:
    idle      0
    b         halt
```

逐条回连：

| 指令 | 回连课次 |
|---|---|
| `la.global $sp` | 第 1、3、4 次课 |
| `bl clear_bss` | 第 2、5、6 次课 |
| `bl kernel_main` | 第 1、6 次课 |
| `idle`/`b` | 第 1 次课 |

另选一条深入（按选题）：`clear_bss` 循环 / `memset`/`strlen`（第 7 次课）/ `exception_entry`（第 9 次课）/ UART `st.b`（第 8 次课）。

## 7. 思考与展望

1. 为什么先移植输出再移植中断？
2. 直映地址与物理地址混淆如何排查？教学内核是否开 MMU 的利弊？
3. 从 miniOS 到通用 OS，调度/地址空间/文件系统/驱动框架，你认为下一步最关键的一块是什么？
4. Agent OS 若要运行不可信技能，最小隔离是什么？

## 8. 结束语（可直接使用）

> 我们不是从 Hello 顺便学点汇编，而是先获得读写机器的能力，再把这种能力用于 miniOS，并指向智能体系统软件。  
> 看见每一条指令如何改变寄存器与内存，是系统能力的起点。
