# 第 1 周课程 PPT 第 1-2 节扩容设计

## 背景与问题

第 1 周课程"从 0 启动一个 LoongArch miniOS"采用四节课结构，其中第 1 节（为什么学习汇编）和第 2 节（LoongArch 最小知识包）连堂上课，对应 90 分钟。

当前 `scripts/generate_week01_course_ppt.py` 为第 1、2 节生成了 10 张幻灯片：

- 第 1 节（4 张）：章节页、C→CPU 流程图、"用 C 语言经验理解汇编"要点、"第一节课堂活动"。
- 第 2 节（6 张）：章节页、学习目标、寄存器表、两张指令例子、"第二节练习"。

问题诊断：

1. **讲义已有但幻灯片缺失的内容**：讲义 `docs/week01/week01_qemu_hello_lecture_notes.md` 中 4.3"为什么选择 LoongArch"、5.4"寻址方式一句话理解"两节内容存在，但从未做成幻灯片，学生课堂上看不到。
2. **"课堂活动"与"练习"内容单薄且与前文重复**：现有"第一节课堂活动"幻灯片基本是在复述 4.1 导入问题里已经问过的两个问题，没有提供新的操作或新的认知增量；两张活动/练习幻灯片都没有时间标注、没有参考答案，教师难以把控并撑满时长。
3. **缺少真实例子的逐行拆解**："用 C 语言经验理解汇编"停留在抽象类比，没有一个完整的、逐行讲解的汇编例子帮助学生建立具体印象。
4. **没有时间预算指引**：教师不知道每张幻灯片该停留几分钟，容易前松后紧。

此外，核实文件路径时发现：`scripts/generate_week01_course_ppt.py` 中 `OUT` 常量指向 `docs/week01_qemu_hello_course.pptx`，但仓库重组（"Organize docs by teaching week" 提交）后实际课件路径已迁移到 `docs/week01/week01_qemu_hello_course.pptx`。本次修改需要一并修正该常量，否则脚本会在错误位置生成新文件。

**已知风险（非本次处理范围，仅记录）**：`docs/week01/` 目录下存在一个未跟踪的 `week01_qemu_hello_course_v2 (1).pptx`，疑似手工导出/编辑的重复文件。本次不会读取或覆盖它，如需处理需用户确认这是否是需要保留的手工修改版本。

## 目标

在保持"第一周只建立最小可验证链路"教学边界的前提下，把第 1+2 节内容和节奏扩充到能扎实撑满 90 分钟，且新增内容都必须：

- 与现有讲义内容对齐或反哺讲义（不能只改 PPT、不改讲义，二者要保持一致）；
- 符合 AGENTS 反幻觉口径——凡是"示意性"编译输出（本机 Windows 环境未装 LoongArch 交叉工具链，无法现场编译验证），必须在幻灯片和讲义中明确标注"教学示意，非本机实测编译输出"，并提示教师如有工具链应现场编译替换为真实输出。

## 架构

沿用现有实现方式：`scripts/generate_week01_course_ppt.py` 用 `python-pptx` 通过一组可复用的 slide-builder 函数（`add_bullet_slide` / `add_code_slide` / `add_flow_slide` / `add_table_slide` / `add_section_slide`）拼装 `build()` 函数里的幻灯片序列。本次扩容在同一模式下新增/泛化少量 builder 函数，不引入新的技术栈。

新增/修改的 builder 函数：

1. **`add_table_slide` 泛化**：当前该函数是为寄存器表硬编码的（标题、表头、行数据都写死在函数体内）。本次改为通用签名 `add_table_slide(prs, heading, subtitle, lesson, headers, rows, col_widths, footer)`，寄存器表和新增的寻址方式表、时间预算表都调用同一个函数。这是随本次需求顺带做的清理，避免函数体内被迫继续硬编码不同内容。
2. **新增 `add_code_annotated_slide(prs, heading, code_text, annotations, subtitle, lesson)`**：左侧窄列放代码块（复用现有代码框样式），右侧列放编号说明要点，用于"真实例子逐行拆解"场景。
3. **新增 `set_speaker_notes(slide, text)`**：写入 `slide.notes_slide.notes_text_frame.text`，用于把时间预算、讲解要点、参考答案嵌入 pptx 文件本身。

数据流不变：脚本运行一次性生成 `docs/week01/week01_qemu_hello_course.pptx`（修正后的路径），无外部依赖、无用户输入、无需错误处理分支——生成失败即脚本异常退出，这对一次性内容生成脚本是合理的。

### 第 1 节新增/扩充内容

**新增幻灯片 A：为什么选择 LoongArch**（对应讲义 4.3，此前未做成幻灯片）

- LoongArch 是国产自主指令集架构，本课程借此建立本土系统软件平台意识。
- 课程链路：LoongArch 汇编 → miniOS → Agent Runtime → Agent OS → 龙芯智能体开发。
- 第一阶段用 QEMU，避开开发板数量、连线、固件问题，先把底层概念学扎实。
- x86、ARM、LoongArch 的机器指令不是一套东西——汇编语言和 CPU 架构强绑定。

讲者备注：时间预算 5 分钟；提醒不展开架构历史和特权级细节。

**新增幻灯片 B+C：真实例子逐行拆解**（`add_code_annotated_slide`）

代码侧（明确标注"教学示意汇编，非本机实测编译输出，如现场有工具链请现场编译替换"）：

```
int add(int a, int b)
{
    return a + b;
}

# 对应 LoongArch 汇编（-O0，教学示意）
add:
    addi.d  $sp, $sp, -16      # 开辟栈空间
    st.w    $a0, $sp, 12       # 参数 a 存入栈
    st.w    $a1, $sp, 8        # 参数 b 存入栈
    ld.w    $t0, $sp, 12       # 取回 a
    ld.w    $t1, $sp, 8        # 取回 b
    add.w   $a0, $t0, $t1      # 计算 a + b，结果放入返回值寄存器
    addi.d  $sp, $sp, 16       # 释放栈空间
    jirl    $zero, $ra, 0      # 返回调用者
```

右侧编号说明对照：① 参数 a、b 通过 $a0/$a1 传入，② 为什么会有栈上存取（-O0 未优化，真实场景会被优化掉）、③ add.w 是唯一"做加法"的指令、④ 返回值放在 $a0、⑤ jirl 配合 $ra 完成返回。

讲者备注：时间预算 12 分钟；强调"这只是示意，不同优化等级/不同编译器版本产出会不同，第一周不要求学生记住确切编码，只要求理解结构"；若课堂机器装有 `loongarch64-linux-gnu-gcc`，建议现场执行 `loongarch64-linux-gnu-gcc -O0 -S -o - add.c` 展示真实输出替换本页。

**扩充幻灯片：课堂活动**（替换现有重复内容，改为新活动，避免与 4.1 导入问题重复）

- 任务：给出新函数 `int max(int a, int b) { return a > b ? a : b; }`（或等价的三元表达式函数）。
- 独立思考（5 分钟）：不写真实汇编语法，只用文字/伪步骤描述 CPU 需要做哪几步（取参数、比较、按结果选值、把结果放到某个位置返回）。
- 小组讨论（5 分钟）：两人一组对比思路，讨论"比较"和"选择"在硬件层面可能对应什么动作（为第 2 节的分支跳转指令做铺垫）。
- 分享（2 分钟）：抽 1-2 组口头说明。

讲者备注：时间预算 12 分钟；参考答案要点——取参数（$a0/$a1）→ 比较（关系比较）→ 条件跳转选择分支 → 结果放入返回值寄存器；提醒教师这里不需要给出真实指令，第 2 节会正式讲分支指令。

### 第 2 节新增/扩充内容

**新增幻灯片：寻址方式**（对应讲义 5.4，此前未做成幻灯片，用泛化后的 `add_table_slide`）

| 方式 | 说明 | 真实例子 |
|---|---|---|
| 寄存器寻址 | 操作数直接在寄存器里 | `add.w $a0, $t0, $t1` |
| 立即数寻址 | 常数直接写在指令里 | `addi.d $sp, $sp, -16` |
| 基址加偏移 | 一个寄存器给基地址，加偏移访存 | `st.w $a0, $sp, 12` |
| PC 相对跳转 | 跳转目标和当前指令位置有关 | `bne $t0, $zero, L1` |

讲者备注：时间预算 8 分钟；不深入编码格式，第一周只要求能看懂启动代码里用到的这几种。

**新增幻灯片：寄存器/指令快速匹配活动**

给出 6 条指令（复用"基础指令例子"幻灯片里的 6 行），要求学生圈出/写出每行里出现的寄存器角色（sp / ra / a0-a7 / t0-t8 / zero）以及这条指令属于算术、访存还是跳转。

讲者备注：时间预算 7 分钟；参考答案表（addi.d→sp，算术；st.d→ra+sp，访存；ld.d→ra+sp，访存；bne→t0，跳转；bl→隐式写 ra，跳转；jirl→zero+ra，跳转）。

**扩充幻灯片：第二节练习**（保留现有 4 条讨论题，新增时间标注 + 参考答案备注）

讲者备注：时间预算 6 分钟；参考答案要点对照讲义 5.3/5.4 已有内容。

**新增幻灯片：小测（选择题）**

1. 下面哪条指令是访存指令？ A) `addi.d` B) `st.d` C) `bne` D) `bl`（答案 B）
2. `$ra` 对应哪个寄存器编号？ A) r0 B) r1 C) r3 D) r12（答案 B）
3. `bl` 指令执行后，哪个寄存器的值一定会被改变？ A) `$sp` B) `$a0` C) `$ra` D) `$zero`（答案 C）
4. 进入 C 函数之前为什么必须先设置好 `$sp`？（简答，留给学生口头回答，不给选项）

讲者备注：时间预算 4 分钟；用于检验本节是否听懂，可现场举手或口头点名回答。
