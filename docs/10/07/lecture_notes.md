# 第 7 次课教师讲义：memset / memcpy / strlen 汇编实现

> 技术编号：`07`　|　建议检查点：`07-libc-asm`（实现见 `lib/string.S`，边界测试见 `kernel/main.c`）  
> **本课不引入新指令、新语法**，考的也不是"能不能说出这是第几次课学的"——
> 而是能不能不看提示，自己把寄存器、访存、循环、调用约定灵活组合起来，
> 读懂一段有点复杂的真实代码，并写出一个真正解决问题的新函数。

## 0. 一句话目标

读懂并写出真正综合运用前面所学的复杂程序：不是三个互相独立的小函数，
而是像 `memmove`（处理内存重叠）、`zero_and_copy`（组合调用三个函数）
这样，必须把寄存器、访存、循环、调用约定灵活拼在一起才能写对的真实功能。

## 1. 课程定位（Why）

### 1.1 库函数是什么，在系统里处于什么位置

**库函数**（library function）是预先写好、编译打包成"库"、可以被任意程序
链接调用的通用功能代码——不用每个程序都重新发明一遍"怎么比较两个字符串"。
在一台跑 Linux 的电脑上，几乎每个 C 程序都会链接 **C 标准库**（libc，常见
实现是 glibc、musl），libc 大致分两类函数：

| 类别 | 例子 | 要不要找内核 |
|---|---|---|
| 系统调用的薄封装 | `read`/`write`/`open`/`fork` | **要**——真正干活的是内核，libc 只是把陷入指令包装成好用的 C 函数 |
| 纯数据处理 | `memcpy`/`memset`/`strlen`/`strcmp` | **不要**——只操作已经在自己进程地址空间里的内存，不涉及内核 |

第一类正是第 8 次课 `sys_write` 要学的东西；**本课的六个函数全部属于第
二类**——这也是为什么它们可以在还没有系统调用、还没有异常机制的第 7 次课
就先讲：它们不依赖操作系统提供任何服务，只靠寄存器和内存本身就能实现。

### 1.2 miniOS 为什么要自己写这些函数

打开 `Makefile` 会看到 `-ffreestanding -nostdlib`：告诉编译器"不要假设
存在一个宿主环境的标准库"。这不是随手加的选项——**miniOS 自己就是操作
系统，它下面没有另一个操作系统替它提供 libc**。普通 Linux 程序调用
`memcpy` 时，链接器会把它接到 glibc 里；miniOS 调用 `memcpy` 时，能接的
只有 `lib/string.S` 里我们自己写的这份实现。

所以 `memset`/`memcpy`/`strlen`/`memmove`/`strcmp`/`zero_and_copy`
**就是 miniOS 自己动手写的一份最小 libc**——函数签名（`void *memset(void
*s, int c, size_t n)` 这种写法）照抄的是 C 标准规定的原型，不是miniOS
自己发明的接口；`include/string.h` 的角色，和真实 libc 的头文件完全一样：
声明"这个符号存在、长这样"，具体实现留给链接器去找。

### 1.3 库函数的底层机制：链接器怎么把调用接到实现

教材不讲这部分，但既然我们在从裸机往上搭一个操作系统，这一层的机制必须
自己讲清楚——否则"调用 memcpy 就能跑"会一直是一句魔法。

**① 静态链接 vs 动态链接**：现实中的库函数有两种接入方式。

| 维度 | 静态链接 | 动态链接 |
|---|---|---|
| 库代码放在哪 | 直接拷贝进最终可执行文件 | 留在共享库文件（`.so`/`.dll`），运行时才加载 |
| 可执行文件大小 | 更大——包含用到的库代码 | 更小——只留一条"去哪找"的引用 |
| 多进程能否共用内存里同一份库代码 | 不能，各自一份 | 能，还可以单独升级库文件而不重新编译程序 |

**miniOS 只能用静态链接**：动态链接依赖操作系统提供"加载器"（运行时把
`.so` 映射进进程地址空间、解析符号），而"提供加载器"本身就是操作系统
要实现的能力之一——miniOS 现在还在搭地基，这一层还没建，所以本课六个
函数只能被直接编译进 `minios.elf`，没有第二个选项。

**② 从一行调用到真正跑起来**：`memcpy(dst, src, n)` 这行 C 代码，要经过
四步才变成能执行的指令：

```text
① 编译：memcpy(...) 在 kernel/main.o 里只留下一个"待解析"的符号引用
② 链接器扫描：把 Makefile 列出的所有 .o 和库文件都翻一遍，找 memcpy 的定义
③ 回填地址：把调用点的占位地址改写成 memcpy 的真实地址（这一步叫"重定位"）
④ 生成镜像：得到地址完整、真正能跑的 minios.elf
```

关键点：**链接器只认"符号名"，不认"语言"**。`kernel/main.c` 里的调用点
不关心 `memcpy` 这个符号最终在哪个文件、用什么语言实现，链接器负责把
两边接上——这也是为什么 C 代码可以调用汇编写的函数，反过来也一样。

**③ miniOS 链接的边界**：链接器只会在 `Makefile` 的 `SRCS_C`/`SRCS_S`
列出的文件里找符号，**没有列进去的文件，链接器根本不知道它存在**——
这不是比喻，是真实会发生的事：如果 `lib/string.S` 里忘记实现
`memcpy`，`make` 到链接这一步会直接报错 `undefined reference to
'memcpy'`，整个构建失败。普通 Linux 程序遇到同样情况时，链接器还能
退一步去系统的 `/usr/lib` 之类的路径找 glibc；miniOS 因为
`-nostdlib`，连这条退路都没有——每一层能力都得自己先写出来，才能被
上面的代码用上，这正是"从裸机搭操作系统"的真实处境。

### 1.4 现实中，库函数和汇编是什么关系

这类函数在现实世界里**几乎从来不是"随便写的 C 代码"**：glibc 里
`memcpy`/`memset`/`strlen`/`strcmp` 这些函数，长期以来都是手写汇编（或者
用专门脚本按 CPU 特性生成的汇编），而且往往不止一个版本——运行时会按
CPU 实际支持的指令集（x86 的 SSE2/AVX2/AVX-512、ARM 的 NEON）挑选最快的
一份来跑，这套机制叫 **IFUNC**（indirect function，间接函数）。原因很直接：
这几个函数是几乎所有程序的"热路径"（调用频率极高），逻辑又足够小、足够
规整，很值得手工榨干性能——本课 §4.5 讲的"8 字节批量搬运"，正是这个思路
的教学缩小版：真实实现一次搬的是 16/32/64 字节、用的是向量寄存器，但
"先处理不对齐的头部、再批量、再处理尾部残余"这个核心逻辑完全一样。

更重要的一点：**C 和汇编在"函数调用"这个层面是完全平等的**。编译器看到
一行 `memcpy(dst, src, n)`，只知道要按 ABI（第 6 次课的调用约定）把参数
放进 `$a0`/`$a1`/`$a2`，然后跳到符号 `memcpy`——它既不关心、也不需要知道
这个符号背后是用 C 写的还是用汇编写的，两者对调用方而言完全等价。这正是
本课在做的事：把"C 代码看不见的那一层"，用汇编亲手实现出来。

### 1.5 本课的位置

第 2 次课已经**调用**过 `memset`/`memcpy`/`strlen`；第 3–6 次课依次补齐了
寄存器与基础指令、访存、分支循环、调用约定。这些知识现在都学过了，
本课不是把它们再逐一点名验收一遍，而是检验一件更重要的事：**不看提示，
能不能自己把它们攒成一个真正解决问题的程序**。

课程顺序是这样安排的，一个比一个更综合：

```text
memset / memcpy / strlen   —— 基础：每个函数只用一种循环骨架
        ↓
memmove                    —— 复杂一点：要先判断方向，再选一条路径执行
        ↓
strcmp                     —— 复杂一点：循环有两条不同的退出路径
        ↓
zero_and_copy              —— 最复杂：非叶子函数，组合调用前面三个函数
```

到 `zero_and_copy` 这里，代码已经不是"看一眼就知道在干什么"的水平了——
这才是本课真正想练的能力：读懂、能改、能仿照着写出新的。

## 4. 课程知识

### 4.1 参数约定复习

| 函数 | `$a0` | `$a1` | `$a2` | 返回 |
|---|---|---|---|---|
| `memset` | dst | byte | n | 原 dst |
| `memcpy` | dst | src | n | 原 dst |
| `strlen` | s | — | — | 长度 |

三个函数参数个数不同，套用的是同一套调用约定：前几个整数/指针参数走
`$a0`-`$a2`，返回值在 `$a0`。

### 4.2 memset

```asm
memset:
    move        $t0, $a0
    beqz        $a2, 2f
1:
    st.b        $a1, $a0, 0
    addi.d      $a0, $a0, 1
    addi.d      $a2, $a2, -1
    bnez        $a2, 1b
2:
    move        $a0, $t0
    jr          $ra
```

`$t0` 先保存原始 `dst`，因为 `$a0` 接下来要当游标用，返回前得把它换回来。
`n==0` 时 `beqz` 直接跳过循环，一次都不写，保证不越界。循环体每轮写一个
字节、指针 `+1`、计数 `-1`，`bnez` 判断计数是否归零决定要不要回跳。全程
没有 `bl`，是叶子函数，不用保存 `$ra`。

### 4.3 memcpy

```asm
memcpy:
    move        $t0, $a0
    beqz        $a2, 2f
1:
    ld.bu       $t1, $a1, 0
    st.b        $t1, $a0, 0
    addi.d      $a0, $a0, 1
    addi.d      $a1, $a1, 1
    addi.d      $a2, $a2, -1
    bnez        $a2, 1b
2:
    move        $a0, $t0
    jr          $ra
```

和 `memset` 骨架一样，差别是先 `ld.bu` 再 `st.b`——必须用无符号加载，
否则 `0x80` 这类高位字节会被符号扩展成垃圾值；而且这次要同时维护两个
指针（`$a0` 追 dst，`$a1` 追 src），各自 `+1`。

**教学版边界**：假设 `dst`/`src` 区间不重叠。区间重叠时这个实现会出错——
下面 §4.6 的 `memmove` 就是用来解决这个问题的。

### 4.4 strlen

```asm
strlen:
    move        $t0, $a0
1:
    ld.bu       $t1, $a0, 0
    beqz        $t1, 2f
    addi.d      $a0, $a0, 1
    b           1b
2:
    sub.d       $a0, $a0, $t0
    jr          $ra
```

`$t0` 记住起点，循环靠读到 `'\0'`（而不是计数器）判断结束，最后
`sub.d` 用当前地址减起点算出长度。契约：传入的内存里必须有 `'\0'`，
否则会一直读下去，直到越界。

### 4.5 优化讨论：访存对齐的真实工程问题（不必一次实现）

不要求实现，但值得课堂展开推演：

1. **8 字节批量**：把逐字节的 `st.b`/`ld.bu` 换成 `st.d`/`ld.d`，理论上快 8 倍。
2. **但地址不一定对齐**：如果 `dst` 起始地址不是 8 的倍数，直接用 `st.d`
   可能触发未对齐异常（平台相关）。真实实现要分三段：
   - 先逐字节处理到 8 字节对齐边界；
   - 中间用 `st.d` 按 8 字节批量处理；
   - 结尾不足 8 字节的残余部分，再逐字节处理一次。
3. **循环展开**：减少 `bnez` 分支次数，代价是代码变长、更难读。
4. **正确性永远优先于速度**——今天写的逐字节版本就是这个三段式优化中间
   那一段在不追求性能时的合理简化，不是"没做优化"。

### 4.6 更复杂的例子：`memmove`

`memcpy` 有一个明确写在契约里的限制：区间重叠时结果不保证正确。
`memmove` 就是用来解决这个问题的真实函数——读懂它，是本课"读复杂例子"
这个目标的第一次实战：

```asm
memmove:
    move        $t0, $a0            /* 保存原始 dst，作为返回值。 */
    beqz        $a2, 4f             /* n==0：什么都不用做。 */

    sltu        $t2, $a0, $a1       /* t2 = (dst < src) ? 1 : 0 */
    bnez        $t2, 2f             /* dst < src：正向搬，和 memcpy 一样 */

    /* dst >= src：从尾往前搬，先把两个指针都移到最后一个字节 */
    add.d       $a0, $a0, $a2
    add.d       $a1, $a1, $a2
    addi.d      $a0, $a0, -1
    addi.d      $a1, $a1, -1
1:
    ld.bu       $t1, $a1, 0
    st.b        $t1, $a0, 0
    addi.d      $a0, $a0, -1
    addi.d      $a1, $a1, -1
    addi.d      $a2, $a2, -1
    bnez        $a2, 1b
    b           4f

2:
    ld.bu       $t1, $a1, 0
    st.b        $t1, $a0, 0
    addi.d      $a0, $a0, 1
    addi.d      $a1, $a1, 1
    addi.d      $a2, $a2, -1
    bnez        $a2, 2b

4:
    move        $a0, $t0
    jr          $ra
```

**先读懂它在解决什么问题，再看代码**：如果 `dst` 在 `src` 后面且区间重叠
（比如把一段数据整体右移几个字节），从头往前搬会先用新值覆盖掉还没读到的
旧值——数据被自己污染了。解法是判断方向：`dst < src` 时正向搬和 `memcpy`
完全一样（永远读在写前面）；`dst >= src` 时反过来，从最后一个字节开始
往前搬，读写顺序倒转，同样保证"永远读在写前面"。

`sltu` 是 `slt` 的无符号版本——比较两个地址必须按无符号理解，这里第一次
用到，含义和 `slt` 完全类似，只是不把最高位当符号位看。

**课堂建议**：不要直接讲代码在做什么，先让学生自己读——给一个具体例子
（比如 `memmove(buf, buf+2, 6)` 和 `memmove(buf+2, buf, 6)`），让学生
predict 结果，再对照 §4.9 的真实输出核对。读不懂就带着走一遍两条路径，
但**先给机会自己读**，这是本课真正的训练点。

### 4.7 更复杂的例子：`strcmp`

```asm
strcmp:
1:
    ld.bu       $t0, $a0, 0       /* t0 = *a */
    ld.bu       $t1, $a1, 0       /* t1 = *b */
    bne         $t0, $t1, 2f      /* 字节不同：跳出去算差值 */
    beqz        $t0, 3f           /* 两边都读到 '\0'：字符串相等 */
    addi.d      $a0, $a0, 1
    addi.d      $a1, $a1, 1
    b           1b
2:
    sub.d       $a0, $t0, $t1
    jr          $ra
3:
    move        $a0, $zero
    jr          $ra
```

前面几个函数的循环只有一条退出路径；`strcmp` 的循环有两条：`bne` 判
"两个字节不同，提前跳出去算差值"，`beqz` 判"两边同时读到 `'\0'`，正常
结束、返回 0"。两条路径通向不同的返回值——读代码时先问自己"这个循环
什么时候会退出、退出的时候是哪种情况"，再看它退出后做了什么，会比逐行
硬翻译轻松很多，这也是读复杂代码通用的方法。

`int strcmp(const char *a, const char *b)`：0 表示相等，非 0 是第一个
不同字节的差值（教学简化，不做饱和处理）。叶子函数，两个参数进、一个
整数返回。

### 4.8 更复杂的例子：`zero_and_copy`（非叶子函数）

前面所有函数都是叶子函数。`zero_and_copy` 不是——它内部真的调用了别的
函数，是本课"综合"程度最高的一个例子：

```asm
zero_and_copy:
    addi.d      $sp, $sp, -32
    st.d        $ra, $sp, 24
    st.d        $s0, $sp, 16     /* s0 = dst，跨三次 bl 保存 */
    st.d        $s1, $sp, 8      /* s1 = src，跨三次 bl 保存 */

    move        $s0, $a0
    move        $s1, $a1

    move        $a1, $zero        /* memset(dst, 0, dst_size) */
    bl          memset

    move        $a0, $s1          /* strlen(src) */
    bl          strlen

    move        $a2, $a0          /* memcpy(dst, src, len) */
    move        $a1, $s1
    move        $a0, $s0
    bl          memcpy

    ld.d        $ra, $sp, 24
    ld.d        $s0, $sp, 16
    ld.d        $s1, $sp, 8
    addi.d      $sp, $sp, 32
    jr          $ra
```

`void *zero_and_copy(void *dst, const char *src, size_t dst_size)`：
先把整块 `dst` 清零，再把 `src` 的内容搬进去。内部依次 `bl memset`/
`bl strlen`/`bl memcpy`，三次调用意味着 `$ra` 必须先存后取；而
`dst`/`src` 要跨这三次调用存活，`$a0`-`$a2`/`$t0`-`$t8` 都会被三个被调用者
自由覆盖，所以借用 `$s0`/`$s1`（callee-saved，被调用者用了必须原样归还）。

**附带的好处**：因为先 `memset` 清零，只要 `dst_size > strlen(src)`，
结果天然以 `'\0'` 结尾——单独调用 `memcpy` 做不到这一点。这是把两个函数
组合起来才能看到、拆开单独看看不到的性质。

### 4.9 真实调用与验收（`kernel/main.c`）

```c
char greet[16];
zero_and_copy(greet, "hi7", sizeof(greet));
printk("zero_and_copy: greet=\"");
printk(greet);
printk("\"\n");

if (strcmp(greet, "hi7") == 0) {
    printk("strcmp verified: greet == \"hi7\"\n");
}
if (strcmp(greet, "hi8") != 0) {
    printk("strcmp verified: greet != \"hi8\"\n");
}

char left[8]  = { 'A', 'B', 'C', 'D', 'E', 'F', 'G', 'H' };
char right[8] = { 'A', 'B', 'C', 'D', 'E', 'F', 'G', 'H' };

memmove(left, left + 2, 6);          /* dst < src：整体左移 2 位 */
memmove(right + 2, right, 6);        /* dst > src：整体右移 2 位 */
```

真实串口输出（`make run` 实测）：

```text

memset n=1 : buf[0]='Z' buf[1]='X' (应为 Z / X)
memcpy n=0: dst[0]='X' (应仍为 X，未改动)
memcpy n=1: dst[0]='A' dst[1]='X' (应为 A / X)
strlen ""  : len = 0 (应为 0；非空串已在第 5 次课验收)
zero_and_copy: greet="hi7"
strcmp verified: greet == "hi7"
strcmp verified: greet != "hi8"
memmove left  (dst<src): CDEFGHGH (期望 CDEFGHGH)
memmove right (dst>src): ABABCDEF (期望 ABABCDEF)
week07-libc-asm check done
```

`memmove left`：`left+2` 到 `left+7` 的内容（`CDEFGH`）搬到 `left`
开头，末两位保持原样，结果 `CDEFGHGH`。`memmove right`：`right` 开头
6 字节（`ABCDEF`）搬到 `right+2`，前两位保持原样，结果 `ABABCDEF`。
两个结果都和方向判断预测的一致。

## 8. 思考与拓展

1. `memset` 的 `$a1` 只有低 8 位有意义吗？
2. 为何返回 dst 而不是 void？
3. 编译器何时内联类似序列？
4. `strcmp` 里 `sub.d $a0, $t0, $t1` 直接拿字节差值当返回值——如果两个字节
   分别是 `0xff` 和 `0x01`，这个差值符号对不对？（提示：结合 `ld.bu` 的
   零扩展，想清楚 `$t0`/`$t1` 里到底是什么值。）
5. `memmove` 里如果 `dst == src`，会走哪条路径？结果对不对？
6. 如果 `zero_and_copy` 调用方传入的 `dst_size` 小于 `strlen(src)`，会发生
   什么？这算 `zero_and_copy` 的 bug，还是调用方没遵守契约？
