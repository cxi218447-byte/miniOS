> 这是写给你的一份"补教材"：这次课的内容课本没有，PPT 又比较浓缩，如果你只看 PPT

## 0. 先说清楚：这次课到底在讲什么

一句话：**我们要给 miniOS 亲手写一份"最小工具箱"**——`memset`（把一块内存清成某个
值）、`memcpy`（把内存从一个地方搬到另一个地方）、`strlen`（量字符串多长）、以及三个
更复杂一点的 `memmove`/`strcmp`/`zero_and_copy`。这几个名字你可能眼熟——写 C 程序时
天天在用，这次课要做的是：**打开它们的"黑箱"，自己写一遍内部实现**。

在讲代码之前，先花点篇幅说清楚"为什么"——这部分抽象，但不讲清楚，后面的代码会变成
"能跑但不知道为什么这么写"的死记硬背。

## 1. 库函数是什么：先看一个生活场景

设想你去宜家买了一套没装好的书架，说明书里写着"第 3 步：用十字螺丝刀拧上 A4 螺丝"。
你不会因为这句话就重新发明"螺丝刀"——螺丝刀是早就存在、谁都能拿来用的通用工具，
你只管用它，不用管它是怎么造出来的。

**库函数（library function）** 就是编程世界里的"螺丝刀"：别人已经写好、编译打包成
一个"库"，任何程序都可以直接拿来调用的通用功能代码。你写 C 程序时喊一声
`memcpy(dst, src, n)`，就像喊一声"把螺丝刀递给我"——不用重新发明"怎么把一块内存
的内容搬到另一块内存"。

在一台跑 Linux 的电脑上，几乎每个 C 程序都会链接 **C 标准库**（libc，常见实现是
glibc、musl），libc 里的函数大致分两类，就像"工具箱里的工具"也分两种：

| 类别 | 生活类比 | 例子 | 要不要"叫外面的人"帮忙 |
|---|---|---|---|
| 系统调用的薄封装 | 打电话给物业报修水管 | `read`/`write`/`open`/`fork` | **要**——真正干活的是操作系统内核，libc 只是帮你把"打电话"这个动作包装得更好用 |
| 纯数据处理 | 自己在家用螺丝刀拧螺丝 | `memcpy`/`memset`/`strlen`/`strcmp` | **不要**——只摆弄自己家里（自己进程的内存）已经有的东西，不需要向内核求助 |

第一类是第 8 次课 `sys_write` 要学的东西；**这次课的六个函数全部属于第二类**——
这也是为什么它们可以在 miniOS 还没有系统调用、还没有异常机制的这次课就先讲：它们
不依赖操作系统提供任何服务，只靠寄存器和内存本身就能实现，就像在家拧螺丝不需要
先打电话给物业。

## 2. miniOS 为什么要自己写这些函数：搬到荒岛的比喻

正常写 C 程序，你从来不用自己实现 `memcpy`——因为你的程序运行在 Linux 之上，
Linux 已经把 glibc 准备好了，你只管调用。这就像住在正常小区里，水电煤、垃圾清运
都有物业负责，你只管拧开水龙头。

但 **miniOS 自己就是操作系统**——它下面已经没有另一个操作系统替它准备好 libc 了。
这就像你被空投到一座荒岛：没有物业、没有自来水公司，你要用水，得自己挖井、自己
净化。miniOS 要用 `memcpy`，也没有"物业"（宿主操作系统）替它准备好，只能自己动手写。

打开仓库的 `Makefile` 会看到 `-ffreestanding -nostdlib` 这两个选项，翻译成人话就是
"告诉编译器：别以为这个程序底下还有个操作系统帮你兜底"。所以 `memset`/`memcpy`/
`strlen`/`memmove`/`strcmp`/`zero_and_copy` 这六个函数，**就是 miniOS 自己动手挖的
一口井**——是我们给这座荒岛写的最小一份 libc。

`include/string.h` 里的函数声明（比如 `void *memset(void *s, int c, size_t n)`），
抄的是 C 标准里规定的"标准接口长什么样"，不是 miniOS 自己发明的写法——就像不管
哪个国家产的螺丝刀，握把形状可以不同，但拧的螺丝规格是统一标准，这样才能互相兼容。

## 3. 链接器：怎么把"喊一声"接到"真正干活的代码"

这一节最抽象，但理解它，你才会明白"C 代码为什么能调用汇编写的函数"这件事到底是
怎么发生的。

### 3.1 静态链接 vs 动态链接：买断家具 vs 去图书馆借书

现实中的库函数有两种"接入"方式，用搬家来类比：

| 维度 | 静态链接：买断家具搬进新家 | 动态链接：去图书馆借书 |
|---|---|---|
| 东西放在哪 | 家具直接搬进你家，成为你家的一部分 | 书留在图书馆，你只留一张借书证 |
| 你的"家"（可执行文件）体积 | 更大——包含了你用到的全部家具 | 更小——只留一条"上哪儿借"的记录 |
| 多户人家能不能共用同一件东西 | 不能，各自买一份、各自占地方 | 能，图书馆一本书可以被很多人先后借阅，还能单独换新版而不影响你家其他布置 |

**miniOS 只能"买断"（静态链接）**：动态链接依赖操作系统提供一个"加载器"——运行时
把"图书馆的书"（共享库文件 `.so`/`.dll`）现场搬到你家、现场记账。而"提供加载器"
本身就是操作系统要实现的能力之一——miniOS 现在还在打地基，这层能力还没盖出来，所以
这次课的六个函数只能被直接编译进 `minios.elf`，没有第二个选项。

### 3.2 从一行调用到真正跑起来：写信只写地址

`memcpy(dst, src, n)` 这行 C 代码，要经过四步才变成能在 CPU 上真正执行的指令：

```text
① 编译：这行调用在 kernel/main.o 里只留下一个"待解析"的符号引用（相当于信封上写了收件人名字，但还不知道具体住哪）
② 链接器扫描：把 Makefile 列出的所有 .o 和库文件都翻一遍，找 memcpy 的真实定义（邮局翻花名册，查这个名字住哪栋楼）
③ 回填地址：把调用点的占位地址改写成 memcpy 的真实地址（在信封上盖上真实门牌号，这一步叫"重定位"）
④ 生成镜像：得到地址完整、真正能跑的 minios.elf（信真的能送到了）
```

关键点：**链接器只认"符号名"（收件人姓名），不认"语言"（这个人是哪国人）**。
`kernel/main.c` 里的调用点不关心 `memcpy` 这个符号最终在哪个文件、用什么语言实现——
链接器负责把两边接上。这正是为什么 **C 代码可以调用汇编写的函数，反过来也一样**：
写信的人只管写对地址，不用管收信人用什么语言回信。

### 3.3 miniOS 链接的边界：点了菜单上没有的菜

链接器只会在 `Makefile` 的 `SRCS_C`/`SRCS_S` 列出的文件里找符号——**没有列进去的
文件，链接器根本不知道它存在**。这不是比喻，是真会发生的事：如果 `lib/string.S`
里忘了实现 `memcpy`，`make` 到链接这一步会直接报错 `undefined reference to
'memcpy'`，整个构建失败。

这就像你去一家餐馆，点了一道菜单上根本没有的菜——老板不会含糊地给你端点别的东西
凑数，而是直接告诉你"没有这道菜"。普通 Linux 程序遇到"没写这道菜"的情况时，链接器
还能退一步去系统的 `/usr/lib` 之类的"其他餐馆"找 glibc；miniOS 因为
`-nostdlib`，连这条退路都没有——每一层能力都得自己先写出来，才能被上面的代码用上，
这正是"从裸机搭操作系统"的真实处境：**没有外卖可以点，只能自己下厨**。

## 4. 现实中，库函数和汇编是什么关系：不同体质开不同的处方

这类函数在现实世界里几乎从来不是"随便写的 C 代码"：glibc 里的 `memcpy`/`memset`/
`strlen`/`strcmp`，长期以来都是手写汇编（或者用专门脚本按 CPU 特性生成的汇编），而且
往往不止一个版本——运行时会按 CPU 实际支持的指令集（比如 x86 的 SSE2/AVX2/AVX-512、
ARM 的 NEON）挑选最快的一份来跑，这套机制叫 **IFUNC**（indirect function，间接函数）。

这就像去医院体检：医生不会给所有人开同一张处方，而是先看你的体质报告（CPU 支持
哪些指令集），再从"处方库"里选一张最适合你体质的方案（挑一份用了对应指令集、跑得
最快的实现）。原因很直接：这几个函数是几乎所有程序的"热路径"（调用频率极高），
逻辑又足够小、足够规整，很值得手工榨干性能——这次课 §6 讲的"8 字节批量搬运"，
正是这个思路的教学缩小版：真实实现一次搬的是 16/32/64 字节、用的是向量寄存器，
但"先处理不对齐的头部、再批量、再处理尾部残余"这个核心思路完全一样。

更重要的一点：**C 和汇编在"函数调用"这个层面完全平等**。编译器看到一行
`memcpy(dst, src, n)`，只知道要按 ABI（第 6 次课的调用约定）把参数放进
`$a0`/`$a1`/`$a2`，然后跳到符号 `memcpy`——它既不关心、也不需要知道这个符号背后
是用 C 写的还是用汇编写的，两者对调用方而言完全等价。这正是这次课在做的事：
把"C 代码看不见的那一层"，用汇编亲手实现出来。

## 5. 六个函数逐个讲解：每个都配一个生活类比

读代码前，先想清楚"这个函数在生活里对应什么动作"，再去看汇编怎么把这个动作拆成
一步步机器指令——这样读代码时不会迷失在助记符里，而是始终知道"现在这一步在干什么"。

### 5.1 `memset`：刷墙/铺地砖

把一整块地方涂成同一个颜色——刷墙的时候，你从墙的一角开始，一刷子一刷子地涂，直到
涂满整面墙才停手，不会漏掉一块也不会多刷出界。

```asm
memset:
    move        $t0, $a0
    beqz        $a2, 2f
1:
    st.b        $a1, $a0, 0
    addi.d      $a0, $a0, 1
    addi.d      $a2, $a2, -1
    bnez        $a2, 1b
2:
    move        $a0, $t0
    jr          $ra
```

- `$t0` 先记下墙角的起点（原始 `dst`），因为 `$a0` 接下来要当"刷子当前位置"用，
  刷完得把起点还给调用者当返回值。
- `n == 0`（没有墙可刷）时 `beqz` 直接跳过循环，一刷子都不下，保证不会刷到不该刷的
  地方。
- 循环体：涂一个字节（`st.b`）→ 刷子往前挪一格（`+1`）→ 剩余面积减一（`-1`）→
  `bnez` 判断还有没有剩余面积，决定要不要继续刷。
- 全程没有调用别的函数（叶子函数），不用保存 `$ra`。

### 5.2 `memcpy`：复印文件

把一叠文件一页页复印到另一叠——假设两叠纸放在完全不同的桌子上（不重叠），你从
第一页开始，读一页、复印一页，直到印完最后一页。

```asm
memcpy:
    move        $t0, $a0
    beqz        $a2, 2f
1:
    ld.bu       $t1, $a1, 0
    st.b        $t1, $a0, 0
    addi.d      $a0, $a0, 1
    addi.d      $a1, $a1, 1
    addi.d      $a2, $a2, -1
    bnez        $a2, 1b
2:
    move        $a0, $t0
    jr          $ra
```

和 `memset` 骨架一样，差别是先"读一页"（`ld.bu`）再"印一页"（`st.b`）——必须用
**无符号**加载，否则原件上 `0x80` 这类高位字节会被误读成负数（符号扩展出垃圾值）；
而且这次要同时看住两叠纸各自读/印到第几页（`$a0` 追 dst，`$a1` 追 src），各自
往前挪一格。

**这版实现有一个隐藏假设**：两叠纸不重叠（`dst`/`src` 区间不重叠）。如果两叠纸
其实是同一摞纸的不同部分（区间重叠），这个实现会出错——§5.4 的 `memmove` 就是
用来解决这个问题的。

### 5.3 `strlen`：量绳子长度

量一根绳子有多长：从绳头开始，一寸一寸往前量，量到打结的地方就停下，回头看看
量了多少寸——这就是绳子的长度。

```asm
strlen:
    move        $t0, $a0
1:
    ld.bu       $t1, $a0, 0
    beqz        $t1, 2f
    addi.d      $a0, $a0, 1
    b           1b
2:
    sub.d       $a0, $a0, $t0
    jr          $ra
```

`$t0` 记住绳头（起点），循环靠"读到打结处"（字符 `'\0'`）判断结束，而不是靠数
到某个固定数字；最后 `sub.d` 用"当前量到的位置"减去"绳头位置"，算出量了多少寸
（字符串长度）。**契约**：这根绳子必须真的打了结（内存里必须有 `'\0'`），否则
你会一直量下去，量到别人家的墙上去（越界读取）。

### 5.4 `memmove`：同一个书架上挪书

`memcpy` 有个明确的限制：两叠纸不能是同一摞纸的不同部分。但现实中经常需要"把
书架上第 3–8 格的书，整体往左挪 2 格"——这时候源头和目的地是**同一个书架**，
显然有重叠。`memmove` 就是用来解决这个问题的真实函数。

**先想清楚会出什么错，再看代码**：如果不管三七二十一，永远从左往右一本本挪
（先把第 3 格的书挪到第 1 格，再挪第 4 格到第 2 格……），当你去挪第 3 格的书时，
第 3 格的书其实已经被上一步"挪第 5 格到第 3 格"的操作覆盖掉了——你还没读到它，
它就已经被别的书顶替了。这就像叫两个人同时收拾同一列书架，一个人还没来得及看
清楚某格上原来放的什么书，另一个人已经把新书放上去了，原来的信息就丢了。

解法：**先看清楚往哪个方向挪，再决定从哪头开始**：

```asm
memmove:
    move        $t0, $a0            /* 保存原始 dst，作为返回值 */
    beqz        $a2, 4f             /* n==0：什么都不用做 */

    sltu        $t2, $a0, $a1       /* t2 = (dst < src) ? 1 : 0 */
    bnez        $t2, 2f             /* dst < src：正向搬，和 memcpy 一样 */

    /* dst >= src：从尾往前搬，先把两个指针都移到最后一个字节 */
    add.d       $a0, $a0, $a2
    add.d       $a1, $a1, $a2
    addi.d      $a0, $a0, -1
    addi.d      $a1, $a1, -1
1:
    ld.bu       $t1, $a1, 0
    st.b        $t1, $a0, 0
    addi.d      $a0, $a0, -1
    addi.d      $a1, $a1, -1
    addi.d      $a2, $a2, -1
    bnez        $a2, 1b
    b           4f

2:
    ld.bu       $t1, $a1, 0
    st.b        $t1, $a0, 0
    addi.d      $a0, $a0, 1
    addi.d      $a1, $a1, 1
    addi.d      $a2, $a2, -1
    bnez        $a2, 2b

4:
    move        $a0, $t0
    jr          $ra
```

如果目的地（`dst`）在源头（`src`）**后面**且区间重叠（相当于把书往右挪几格），
从头往前挪会先用新书盖掉还没读到的旧书；解法是反过来，**从最后一格开始，往前挪**，
读写顺序倒转，就能保证"永远先读完这一格的旧书，再往这一格放新书"。反过来，如果
`dst` 在 `src` **前面**（往左挪），正向挪（和 `memcpy` 一样）本来就没问题：因为
每一步"要读的那格"永远还没被写过。

`sltu` 是 `slt` 的无符号版本——比较两个内存地址必须按无符号数理解（地址不会是
负数），这里第一次用到，含义和 `slt` 类似，只是不把最高位当符号位看。

**动手预测一下**：给定同一个初始数组 `buf`，`memmove(buf, buf+2, 6)` 和
`memmove(buf+2, buf, 6)` 分别会往哪个方向搬？会不会互相踩踏？想清楚了再对照
`lecture_notes.md` §4.9 的真实输出核对。

### 5.5 `strcmp`：对暗号

两个人对暗号：一个字一个字轮流念，只要有一个字对不上，立刻停下，报告"这里不一样"；
如果两边一路念到头（都念到"结束"）还没对不上过，就是"完全一致"。

```asm
strcmp:
1:
    ld.bu       $t0, $a0, 0       /* t0 = *a */
    ld.bu       $t1, $a1, 0       /* t1 = *b */
    bne         $t0, $t1, 2f      /* 字节不同：跳出去算差值 */
    beqz        $t0, 3f           /* 两边都读到 '\0'：字符串相等 */
    addi.d      $a0, $a0, 1
    addi.d      $a1, $a1, 1
    b           1b
2:
    sub.d       $a0, $t0, $t1
    jr          $ra
3:
    move        $a0, $zero
    jr          $ra
```

前面几个函数的循环只有一条退出路径（"量完了/涂完了"）；`strcmp` 的循环有**两条**：
`bne` 判"两个字不一样，提前打断、报告差异"，`beqz` 判"两边同时念到结尾，正常
念完、完全一致"。两条路径对应不同的结果——读这段代码时，先问自己"这个循环什么
时候会退出、退出时是哪种情况"，再看退出后做了什么，会比逐行硬翻译轻松很多，这也是
读复杂代码通用的方法。

`int strcmp(const char *a, const char *b)`：返回 0 表示完全一致，非 0 是第一个
不一样的字对应的差值（教学简化版，不做饱和处理）。叶子函数，两个参数进，一个
整数返回。

### 5.6 `zero_and_copy`：打扫房间再搬新家具

前面五个函数都是"叶子函数"——自己闷头干活，不叫别人帮忙。`zero_and_copy` 不一样，
它像"搬新家"这件事：**先打扫干净空房间（清零），量好新家具尺寸（量字符串长度），
再把家具搬进去（复制内容）**——这是三个独立动作组合成的一件"综合工程"。

```asm
zero_and_copy:
    addi.d      $sp, $sp, -32
    st.d        $ra, $sp, 24
    st.d        $s0, $sp, 16     /* s0 = dst，跨三次 bl 保存 */
    st.d        $s1, $sp, 8      /* s1 = src，跨三次 bl 保存 */

    move        $s0, $a0
    move        $s1, $a1

    move        $a1, $zero        /* memset(dst, 0, dst_size) */
    bl          memset

    move        $a0, $s1          /* strlen(src) */
    bl          strlen

    move        $a2, $a0          /* memcpy(dst, src, len) */
    move        $a1, $s1
    move        $a0, $s0
    bl          memcpy

    ld.d        $ra, $sp, 24
    ld.d        $s0, $sp, 16
    ld.d        $s1, $sp, 8
    addi.d      $sp, $sp, 32
    jr          $ra
```

`void *zero_and_copy(void *dst, const char *src, size_t dst_size)`：先把整块
`dst`（新房间）清零，再把 `src`（家具）的内容搬进去。内部依次"叫来"`memset`/
`strlen`/`memcpy` 三个"工人"干活——正因为要"叫别人来干活"（`bl`），自己的
返回地址 `$ra` 必须先存好再取（不然干完活不知道回哪儿去了）；而 `dst`/`src`
这两个"这次搬家的关键信息"要在三个工人轮流干活期间一直记得，可 `$a0`-`$a2`/
`$t0`-`$t8` 这些"公共工具"随时会被叫来的每个工人重新拿去用，所以要借用
`$s0`/`$s1`（callee-saved，"借了就得原样归还"的寄存器）专门存起来。

**顺带的好处**：因为先"打扫干净"（`memset` 清零），只要新房间（`dst_size`）比
家具（`strlen(src)`）大，搬完之后天然自带一个"结束标记"（`'\0'` 结尾）——只叫
`memcpy` 一个人干活是做不到这一点的。这是把几件事组合起来才会出现、拆开单独看
看不出来的性质。

## 6. 一个真实工程问题：为什么不干脆一次搬 8 个字节

前面六个函数每次只搬/涂/量一个字节，慢是慢，但简单、容易读懂、不容易出错。
现实世界的库函数会更快，但也更复杂，这里只做课堂讨论、不要求今天实现：

1. **8 字节批量**：把逐字节的 `st.b`/`ld.bu` 换成 `st.d`/`ld.d`，理论上快 8 倍——
   就像刷墙时，一笔刷一整条而不是一个点一个点戳。
2. **但起点不一定对齐**：如果 `dst` 起始地址不是 8 的倍数，直接用 `st.d` 可能
   触发未对齐异常（平台相关）——就像那条整刷的滚筒，如果墙角形状不规则，滚筒
   刷不到犄角旮旯，还得先用小刷子把边角处理好。真实实现要分三段：
   - 先逐字节处理到 8 字节对齐边界（小刷子处理边角）；
   - 中间用 `st.d` 按 8 字节批量处理（滚筒刷大面）；
   - 结尾不足 8 字节的残余部分，再逐字节处理一次（另一处边角）。
3. **循环展开**：减少分支跳转次数，代价是代码变长、更难读——就像把"刷一笔看一眼"
   改成"闭着眼连刷八笔"，更快但更难中途检查有没有刷歪。
4. **正确性永远优先于速度**——今天写的逐字节版本，就是这个"三段式优化"里中间
   那一段在不追求性能时的合理简化，不是"没做优化"，而是"先保证对，再谈快"。
